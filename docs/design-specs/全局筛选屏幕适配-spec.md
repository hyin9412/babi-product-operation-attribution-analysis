# 全局筛选屏幕适配

## 规范映射
- 设计来源：Figma 商品经营透明化，节点 5325:124562。
- 页面框架：沿用透明化分析 Dashboard 的导航、标题、Tab 和固定筛选区域。
- 模块：商品概览、收支分析、成本定价共用全局筛选网格。
- 组件：沿用 AnalysisSelect、MultiFilter、AnalysisMonthPicker、Field 和 Button。
- 功能及交互：保持筛选顺序、默认值、联动、查询提交、校验和展开收起行为。
- 五项映射通过；本次只调整既有模块的响应式布局。

## 布局契约
- 1280px 屏幕：筛选容器 1016px，3 列，每列约 320px。
- 1440px 屏幕：筛选容器 1176px，4 列，每列约 277px。
- 1920px 屏幕：筛选容器 1656px，5 列，每列约 315.2px。
- 用户确认的新规则：选择器宽度范围为 276–320px，按筛选容器实际可用宽度自动增减列数，不再固定屏幕断点。
- 列数 = floor((网格可用宽度 + 12) / (276 + 12))，至少 1 列；各列宽度 = min(320, (可用宽度 - 12 × (列数 - 1)) / 列数)。
- 达到 320px 上限、但不足以增加一列时，右侧保留剩余空间；窄于 276px 的容器使用单列并缩小至容器宽度。
- 1920px 以上继续按容器容量增加列数，例如当前页面 2050px 屏幕可排 6 列，2560px 可排 7 列。
- 全部行使用同一个等宽 CSS Grid，列间距与行间距均为 12px；控件填满所属列。
- 模块内边距为 12px 16px；标题与表单间距为 12px。
- 标签为 13px / 22px，与控件间距为 8px；控件高 32px。
- 查询按钮排在最后一个筛选项之后，与同一行的控件底边对齐；按动态列数判断是否独占新行，从左侧开始且不预留标签空位。
- 校验错误文案不改变查询按钮与同一行控件的对齐关系。
- 现有边框占据 2px，等宽列的实测宽度与设计稿允许小于 1px 的差异。

## 验收
- 三个 Tab 在 1280、1440、1920px 下分别显示 3、4、5 列。
- 各行同列控件左右边缘一致，账期选择器与其他控件等宽等高。
- 查询按钮与控件对齐，必填错误出现时仍保持对齐。
- 检查设计尺寸、动态增列边界、最大宽度留白、窄屏单列兜底和生产构建。
