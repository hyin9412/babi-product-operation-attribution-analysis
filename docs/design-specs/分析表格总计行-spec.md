# 分析表格总计行设计契约

## 页面架构结论

- 页面类型：经营分析 Dashboard。
- 影响模块：收支分析明细表、计费项成本明细表。
- 路由与页面层级保持不变。

## 规范映射清单

- 页面框架命中：`Dashboard_页面框架.md`。
- 模块命中：Dashboard 内容区中的表格模块。
- 组件命中：沿用现有 `TableBlock.Table` 业务封装，并使用底层 Table 的 `summary` 能力。
- 核心功能命中：总计行、固定表头、固定列、横向滚动、合并单元格。
- 交互闭环命中：排序、分页、横向滚动、纵向滚动时，总计行均与当前表格列保持对齐。

## 表格总计行

- 仅有业务总计信息的表格展示总计行，不为无总计口径的表格新增数据。
- 总计行位于表头下第一行；表格纵向滚动时与表头一起固定。
- 总计数据按完整筛选结果计算，不随当前分页切换。
- 维度列不参与汇总时合并为一个单元格，展示“总计”。
- 连续且无可汇总信息的列合并为一个单元格，展示“—”或明确的不汇总原因。
- 有汇总信息的数值列逐列展示并右对齐，沿用原列格式化规则。
- 总计行所有文字统一使用源力 `@body-2 regular`：13px/22px、400；标签、数值、单位和不汇总提示均继承该排版，不单独放大或加粗。
- “总计”按 Text 类型单元格展示，字号与颜色必须和表体 Text 单元格一致：13px、`var(--color-text-1)`。
- 总计行固定为 40px 高；使用容器内部单一描边，左右外框及底边必须连续，不因固定列、合并单元格或横向滚动断开。
- 总计行所有自定义描边统一使用源力 `@color-border-2`，运行时对应 `var(--color-border-2)`；不得混用 `--color-border-3` 或硬编码色值。
- 总计行不单独展示水平滚动条，避免滚动条占用 40px 行高并裁切文字或描边；横向位置由表体滚动同步控制。
- 总计行层级必须高于表体，但描边不得向外延伸或覆盖第一条数据行。
- 总计容器禁止应用 Arco 针对表头滚动条注入的负 margin-bottom。40px 包含 39px 内容与 1px 容器底边，表体必须从总计容器底部开始。
- 表头与总计交界仅使用表头单元格原生底边，总计容器不得叠加顶部 border、outline 或 shadow。
- 横向滚动时，总计行与表头、表体同步滚动；固定列行为与表体一致。

## 组件与样式约束

- 使用 Table 原生 `summary`、`fixed="top"` 与 `colSpan`，不创建独立网格模拟表格行。
- 保持 Table 默认尺寸，不传入 `small` 或 `mini`。
- 使用现有设计 Token 表达背景、边框与文字层级。
- 总计行不参与排序、分页条数和数据行 hover。

## 验收

- 收支分析：单层及双层表头下均正确显示固定总计行。
- 计费项成本：相同单位时分别汇总容量和单位；不同单位时合并对应列并说明不汇总。
- 各表横向滚动、纵向滚动、固定列和分页切换均不产生列错位。
